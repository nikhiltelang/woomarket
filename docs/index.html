WooMarket360 documentation

A multi-tenant marketing and customer-messaging platform: WhatsApp, email, SMS, Instagram, Facebook Messenger and website chat in one shared inbox, with campaigns, a chatbot, automation flows, a CRM with contact timelines, reports, a public API and self-serve billing.

You run one installation. Businesses (tenants) sign up on it and each gets a private workspace. This page covers installing and running the platform, every feature for superadmins and businesses, the integrations, the API and the code.

Key concepts

  • Superadmin: the platform owner. Manages tenants, plans, levels, payments and system settings.
  • Tenant: a business account. Whoever signs up becomes the tenant admin. A tenant's data is private; other tenants' URLs answer "not found".
  • Team member: a user the tenant admin adds, with chosen permissions.
  • WhatsApp number (channel): a connected WhatsApp Business number. Contacts, templates, WhatsApp campaigns and conversations belong to a number; switch numbers with the picker at the top of the app. Email and SMS are account-wide.
  • Plan: what a tenant pays for: limits (numbers, contacts, team members, campaigns), monthly/yearly price and a feature list.
  • Access level: caps and feature switches the superadmin applies on top of plans (messages per month, email, SMS, API, AI, white-label…).
  • Simulators: in development, WhatsApp, email, SMS, payments, Embedded Signup and AI run against built-in simulators so everything works without real accounts. They are never offered in production.

Installation

Requirements

ComponentNotes
Node.js20 or newer (22 recommended)
DatabaseMySQL 8.0.13+ (8.4 recommended), utf8mb4, server time zone UTC (default-time-zone = '+00:00'). MariaDB is not supported; the installer refuses it.
Memory1 GB RAM for the app; 2 GB+ to build on the same machine
DiskWritable uploads/ (logos, email images, inbox attachments) and, for the installer, a writable .env
OptionalRedis 6+ (only to run several servers), Nginx or Caddy for HTTPS

Option A: web installer (recommended)

  1. Build: npm ci && npm run build
  2. Start without a DATABASE_URL (no .env, or one without that line): NODE_ENV=production node dist/index.js
  3. The console prints the address and a one-time setup code (fix it with INSTALL_SETUP_CODE). Open the address and enter the code.
  4. The wizard checks requirements, asks for the MySQL connection (tested live; the database is created if missing), the site name and public URL (optionally demo data), the superadmin account and optionally the platform SMTP server.
  5. Installing creates the tables, plans, templates and settings and writes .env (mode 600, old file backed up) with generated SESSION_SECRET, JWT_SECRET, ENCRYPTION_KEY and WEBHOOK_VERIFY_TOKEN. The app then starts in the same process.

The installer only runs while no DATABASE_URL is set. ENV_FILE=/path uses a different configuration file.

Option B: configure with environment variables

For Docker, PM2 or hosts where runtime files don't persist.

CREATE DATABASE woomarket360 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'woomarket360'@'%' IDENTIFIED BY 'a-strong-password';
GRANT ALL PRIVILEGES ON woomarket360.* TO 'woomarket360'@'%';
NODE_ENV=production
DATABASE_URL=mysql://woomarket360:a-strong-password@127.0.0.1:3306/woomarket360
SESSION_SECRET=<openssl rand -hex 32>
ENCRYPTION_KEY=<openssl rand -hex 32>
APP_URL=https://app.example.com
WEBHOOK_VERIFY_TOKEN=<openssl rand -hex 16>
SEED_SUPERADMIN_PASSWORD=choose-a-strong-password

Then npm ci && npm run build && npm start. On an empty database the first start applies all migrations and creates the plans and the superadmin account (password from SEED_SUPERADMIN_PASSWORD, or random and printed once in the log). New migrations apply automatically on every start.

Keep ENCRYPTION_KEY safe and never change it. It encrypts stored access tokens, API secrets, payment keys and other secrets; changing it makes them unreadable.

URL-encode special characters in the database password: @ → %40, # → %23, % → %25.

Deployment

The app is one Node.js process that serves the web app, API, webhooks and live updates, and runs the background workers (WhatsApp queue, email/SMS, flows, webhooks, scheduled jobs). It needs a process that stays running, WebSockets through the proxy, a persistent uploads/ folder, MySQL 8.0.13+ and HTTPS with the proxy passing X-Forwarded-Proto.

A. VPS with Nginx and PM2 (recommended)

Ubuntu 24.04 example. Point the domain's DNS A record at the server first.

# packages and firewall
adduser deploy && usermod -aG sudo deploy
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs git nginx mysql-server certbot python3-certbot-nginx unzip
npm install -g pm2
# MySQL on UTC with utf8mb4
cat > /etc/mysql/mysql.conf.d/woomarket.cnf <<'EOF'
[mysqld]
default-time-zone = '+00:00'
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
EOF
systemctl restart mysql
mysql -e "CREATE DATABASE woomarket360 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'woomarket360'@'localhost' IDENTIFIED BY 'A-STRONG-PASSWORD';
GRANT ALL ON woomarket360.* TO 'woomarket360'@'localhost'; FLUSH PRIVILEGES;"
# code (as deploy): clone your repo or unzip the release ZIP
cd /home/deploy && git clone <your-repo> woomarket && cd woomarket
npm ci && npm run build
# Nginx + HTTPS (nginx.conf.example handles WebSockets and large uploads)
sudo cp nginx.conf.example /etc/nginx/sites-available/woomarket
sudo sed -i 's/app.example.com/app.yourdomain.com/g' /etc/nginx/sites-available/woomarket
sudo ln -s /etc/nginx/sites-available/woomarket /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo certbot --nginx -d app.yourdomain.com
sudo nginx -t && sudo systemctl reload nginx
# first start: web installer, then PM2
HOST=127.0.0.1 PORT=3000 NODE_ENV=production node dist/index.js   # finish the wizard, then Ctrl+C
pm2 start ecosystem.config.cjs && pm2 save
pm2 startup        # run the printed command so the app starts after a reboot

If nginx -t fails because the certificate doesn't exist yet, comment out the listen 443 block, run certbot, then restore it.

B. Docker

Dockerfile and docker-compose.yml are included. By default the app container connects to a MySQL server outside Docker; a MySQL container is optional.

cp .env.example .env     # SESSION_SECRET, ENCRYPTION_KEY, APP_URL, DATABASE_URL
docker compose up -d --build
docker compose logs -f app
MySQL runs…Host in DATABASE_URL
on the same machine, outside Dockerhost.docker.internal (mapped by extra_hosts, works on Linux)
on another serverthat server's name or IP
in Docker (docker compose --profile mysql up -d --build)mysql

Inside a container 127.0.0.1 is the container itself, not your server.

MySQL on the host must accept connections from Docker:

# /etc/mysql/mysql.conf.d/mysqld.cnf → [mysqld]
bind-address = 0.0.0.0        # or the Docker bridge only: 172.17.0.1
default-time-zone = '+00:00'
CREATE USER 'woomarket360'@'172.%' IDENTIFIED BY 'PASSWORD';
GRANT ALL ON woomarket360.* TO 'woomarket360'@'172.%';

Keep port 3306 closed to the internet (ufw deny 3306). All services use restart: always; run sudo systemctl enable docker so they come back after a reboot. Uploads live in the uploads_data volume. For HTTPS put Nginx in front and publish the app locally only ("127.0.0.1:3000:3000"). The compose file needs Docker Compose v2.20+.

C. Hostinger Business or Cloud hosting

Hostinger's Node.js Web Apps can run the app with limits:

  • Database: these plans only offer MariaDB, which isn't supported. Use a MySQL 8.0.13+ server the app can reach (managed MySQL or a VPS).
  • Files are replaced on each redeploy: uploaded images are lost, and so would be an installer-written .env. Use hPanel environment variables.
  • One instance only (no Redis mode); redeploy instead of using the in-app updater.
  1. Push the project to a private GitHub repository or build the ZIP with npm run build:prod-zip.
  2. hPanel → Websites → Add website → Node.js Apps → GitHub or ZIP.
  3. Build settings: framework Express (or Other), Node 22.x, build command npm run build, entry file dist/index.js.
  4. Environment variables: NODE_ENV=production, DATABASE_URL, SESSION_SECRET, JWT_SECRET, ENCRYPTION_KEY, WEBHOOK_VERIFY_TOKEN, APP_URL, SEED_SUPERADMIN_PASSWORD (optionally SMTP_*). Don't set PORT.
  5. Deploy. The first start creates the tables and the superadmin account.

On a subdomain (e.g. app.yourdomain.com)

Test on the temporary Hostinger address first, then Connect domain in the app's dashboard and enter the subdomain (with other DNS providers, add the record hPanel shows). Wait for SSL, set APP_URL=https://app.yourdomain.com, restart, and use the subdomain in all external settings (Meta and payment webhooks, SSO redirect URIs, widget code). If hPanel says the subdomain is in use, remove it from the main website's subdomains first.

Go-live checklist

  • https://your-domain/api/health returns {"status":"ok","database":"ok"}
  • APP_URL is the public HTTPS address
  • Platform email works (System settings → Notification setting → test)
  • Meta webhook https://your-domain/webhook/global verified with WEBHOOK_VERIFY_TOKEN
  • Meta app secret saved (unsigned webhooks are refused in production)
  • Payment webhooks registered if you sell plans online
  • Backups scheduled

Updates and backups

In-app updater (Superadmin → Extra → Update): upload the release ZIP from npm run build:prod-zip. It backs up the current version, replaces the files, installs dependencies, builds, updates the database and restarts through PM2, showing each step live. If installing dependencies fails it restores the backup; Rollback restores the last backup by hand. Don't upload GitHub's "Download ZIP".

By hand: git pull && npm ci && npm run build && pm2 reload woomarket360 (Docker: docker compose up -d --build). Migrations apply on start.

Backups:

mysqldump --single-transaction woomarket360 | gzip > backups/db-$(date +%F).sql.gz

Also back up uploads/ (or the Docker volume) and .env, and keep ENCRYPTION_KEY with the backups.

Scaling to several servers

  1. Run Redis (Docker profile redis or a managed Redis; rediss:// for TLS).
  2. Superadmin → System settings → Queue & scaling: turn on Redis mode, enter the URL, Test connection. Servers switch within 15 seconds.
  3. Run more servers behind the load balancer, each with its own NODE_APP_INSTANCE (INSTANCES=4 pm2 start ecosystem.config.cjs). Use sticky sessions for Socket.IO.

In Redis mode every server sends; work is claimed atomically in MySQL, scheduled jobs run once across the cluster, WhatsApp sends share a per-number rate limit (MESSAGE_RATE_PER_SECOND; 20 for Coexistence numbers) and live events reach users on any server. If Redis is down for 30 seconds the servers fall back to database polling. Without Redis only instance 0 runs workers and jobs.

Agency (white-label) domains

Agencies point a CNAME at your APP_URL host and verify with a TXT record. Serve their domains with on-demand certificates that ask the app first, e.g. Caddy:

Superadmin guide

Sign in as superadmin. Turn on two-factor authentication under Account.

First steps

  1. System settings → General setting: site name, time zone, currency (plan prices and payments), brand colour.
  2. Logo and favicon, company details and support email.
  3. Notification setting: platform SMTP or Amazon SES for verification codes, notifications, receipts and reports. Send a test.
  4. Plans and Manage levels.
  5. WhatsApp Embedded Signup: your Meta app (how).
  6. Payments if tenants pay online.
  7. System configuration: registration, email verification, passwords, two-factor policy.
  8. Policy pages, Landing page, SEO if the platform is public.

Dashboard

User segments, messaging and marketing totals, daily messages and sign-ups, sign-ins by browser and OS, and server health.

Manage users and levels

Lists: Active, Banned, Email unverified, Mobile unverified, With subscription, All. Per user: ban with a reason (or unban; bulk changes), mark email/mobile verified, edit details, assign a plan (optional coupon) and an access level, reset two-factor authentication, create and delete users. Send notification reaches everyone, admins, team members, superadmins or chosen users in the app (bell) and/or by email.

New sign-ups get the lowest level. Channels lists every connected number on the platform with its tenant, connection method and health.

Plans, coupons and payments

Plans: name, description, monthly and yearly price, limits (numbers, contacts, team members, campaigns; -1 = unlimited), feature list and "popular" badge. The plan named Free is special: new sign-ups start on it (unless a trial is set) and expired paid plans fall back to it. Plans with subscriptions can't be deleted.

Manage coupons: fixed or percentage, lifetime or with an expiry date, usage limit. Applied at online checkout or when you assign a plan; each use is counted once.

Payments: every online payment with tenant, plan, gateway, status (paid, pending, failed, abandoned), total and invoice PDF, plus 30-day revenue and tax.

First steps for a business

  1. Sign up (or sign in with Google/Microsoft if enabled). Confirm your email if asked.
  2. Connect a WhatsApp number: WhatsApp marketing → Settings → Connect number (options).
  3. Set your time zone: Account → Sending preferences.
  4. Set up email and SMS if you use them: Email marketing → Settings, SMS marketing → Settings.
  5. Import contacts: Audience → Contacts → Import (CSV).
  6. Create a template and get it approved by Meta, then send your first campaign.
  7. Add your team: Account → Team.
  8. Optionally: chatbot, automation flows, website widget, Instagram & Messenger.

Your plan's limits and current usage are under Plan & billing.

WhatsApp numbers

WhatsApp marketing → Settings → Connect number. Only the account admin can connect numbers.

MethodWhen to use
Connect with Facebook (Embedded Signup)Recommended. A Facebook popup lets you pick or create your WhatsApp Business account and number. The number is registered with a 6-digit two-step PIN, shown once and later via Show PIN.

Each number card shows health, quality rating, messaging tier and errors. Check health refreshes it (also every 6 hours). Coexistence numbers show how many contacts and messages were copied, with Sync again for 24 hours after connecting. Connecting the same number again reconnects it. Disconnecting deletes the number's contacts, conversations, templates and campaigns.

24-hour window: WhatsApp only allows free-text messages within 24 hours of the customer's last message. Outside it, send an approved template.

Inbox

All conversations for the selected number in real time: WhatsApp, website chat, Messenger and Instagram.

  • Search and filter by status (open, pending, resolved, closed), assignment (mine, unassigned, all) and unread; pin important chats; set a priority and tags on a conversation.
  • Assign a conversation to a teammate (needs inbox:assign); they get a notification.
  • Reply with text; outside the 24-hour window choose a template. On Messenger and Instagram you can send images.
  • Typing indicators and delivery/read ticks update live.
  • AI: suggested replies and a summary with sentiment, intent and urgency (AI assistant).
  • Chatbot: a Bot label on bot messages and Pause bot / resume per chat (chatbot).
  • Click the contact's name to open their profile and timeline.

Contacts, groups and segments

Contacts

  • Add contacts by hand, from incoming messages, the website widget, the API or CSV import.
  • Import: columns name, phone (international format), email, tags (separated by ;). Every other column becomes a custom field. Choose a group, and whether to merge fields into existing contacts. Up to 50,000 rows per file.
  • Export to CSV with custom fields as columns.
  • Custom fields (age, city, birthday…) are usable as merge tags ({{city}}), in segments and in flows.
  • Status: active, inactive, unsubscribed, blocked. Only active contacts receive campaigns.

Groups

Static lists. Add, remove or move contacts between groups; use them as campaign audiences and flow triggers.

Segments

Saved rules evaluated at send time: name, email, phone, source, status, tag, group, date added, last contacted, any custom field, and engagement (opened/clicked an email, clicked an SMS, replied or not on WhatsApp within N days). Match all or any; a live preview shows how many contacts match.

Contact profile and timeline

Click a contact's name in Contacts (or in the inbox). The profile shows details, tags, groups, custom fields and stats (messages in/out, email open rate, SMS, flows, notes), with Open chat, Edit and Add to flow.

The timeline lists everything, newest first and grouped by day: messages on all channels (with who sent them: teammate, chatbot, campaign, flow), campaign and flow emails and SMS (personalised, with opened/clicked/delivered), flows entered and finished, edits (who changed which fields) and team notes. Filter by type and use Show older to go back. Anyone who can reply in the inbox can add notes; authors or admins can delete them.

WhatsApp templates

Templates are pre-approved messages required to start conversations. WhatsApp marketing → Templates:

  • Name (lowercase, digits, underscores), category (Marketing, Utility, Authentication), language.
  • Optional header, body (up to 1,024 characters, variables {{1}}, {{2}}…), optional footer.
  • Up to 10 buttons: quick reply, website URL, phone number.

Submitting sends the template to Meta; status updates (approved, rejected with the reason) arrive automatically. Sync imports templates already in your Meta account.

WhatsApp campaigns

  1. WhatsApp marketing → Campaigns → New. Pick an approved template.
  2. Audience: all contacts, groups, chosen contacts or a segment.
  3. Variables: map each {{n}} to a contact field (name, phone, email, any custom field) or fixed text.
  4. When: now or scheduled; delivery immediately, at a local time or at each contact's best time (details).
  5. Optional A/B test with a second template (winner by read rate).

Campaigns can be paused, resumed and cancelled. Failed sends are retried for temporary errors. Analytics shows sent, delivered, read, replied and failed (per recipient, with error reasons). Replies to a campaign count in its reply rate.

Campaigns

  • Subject, preview text, sender name, reply-to, content (builder or template).
  • Audience: all contacts, a group, a segment or an uploaded CSV of emails.

  • Schedule, local-time or best-time delivery, quiet hours, A/B test on subject or content (winner by opens or clicks).

SMS marketing

SMS marketing → Settings: choose Twilio (Account SID, Auth Token, from number or alphanumeric sender ID), Vonage (API key, API secret, sender) or the simulator. Delivery receipts arrive automatically.

Campaigns: message (with merge tags), audience (all, group, segment, CSV), schedule and delivery timing. The composer counts characters, segments (GSM-7 or Unicode) and estimated credits. Links can be shortened and tracked (with UTM tags); bot clicks are ignored. A/B test a second message (winner by clicks).

Delivery timing and A/B tests

Account → Sending preferences: your time zone, quiet hours (e.g. 21:00–08:00, per channel; messages are held until the quiet hours end, in the contact's time zone) and the default "best time" hour.

Delivery modeMeaning
ImmediatelyAs soon as the campaign starts
Local timeAt a clock time in each contact's time zone (from their phone number or a timezone field)
Best timeAt the hour each contact has engaged most (opens, clicks, reads, replies), else the default hour

A/B tests: choose the share of the audience to test (10–100%, split between A and B) and how long to wait (1–72 hours). The winner (email: opens or clicks; SMS: clicks; WhatsApp: reads) is sent to the rest automatically.

Chatbot and auto-replies

One rule answers each message, checked in this order: a tapped button, keywords, the welcome (first message, or after 24 hours of silence), the away message (outside business hours), the fallback. Within each kind, the higher rule wins.

Messenger and Instagram show buttons as quick replies; the website shows a numbered list. Start with starter rules (welcome menu, opening hours, prices, talk to a person, away message), then edit them.

Business hours & pauses: opening hours per weekday and time zone; how long the bot stays quiet after a teammate replies (also replies typed in Meta's inbox or the WhatsApp Business app) and after a hand-off. The bot also stops if it answers 6 times in 2 minutes (another bot on the other side).

Public API v1

Base URL: https://app.yourdomain.com/api/v1. Create keys under Account → API keys (admin; needs API access on your level). Each key has a name, allowed channels (email, SMS, WhatsApp), an optional default WhatsApp number and expiry. The Secret Access Key is shown once.

Authentication

Basic (over HTTPS): Authorization: Basic base64(ACCESS_KEY_ID:SECRET_ACCESS_KEY).

Signed request: headers X-WM-Access-Key-Id, X-WM-Timestamp (unix seconds, within 5 minutes) and X-WM-Signature = hex HMAC-SHA256 of:

<timestamp>\n<METHOD>\n<path with query, e.g. /api/v1/send>\n<hex SHA-256 of the raw body>
// Node.js
const crypto = require("crypto");
const body = JSON.stringify(payload);
const ts = Math.floor(Date.now() / 1000).toString();
const bodyHash = crypto.createHash("sha256").update(body).digest("hex");
const sig = crypto.createHmac("sha256", SECRET).update(`${ts}\nPOST\n/api/v1/send\n${bodyHash}`).digest("hex");
await fetch("https://app.yourdomain.com/api/v1/send", {
  method: "POST",
  headers: { "Content-Type": "application/json", "X-WM-Access-Key-Id": KEY_ID, "X-WM-Timestamp": ts, "X-WM-Signature": sig },
  body,
});

Signed requests can't be replayed. Wrong keys, secrets or signatures all return 401.

Request pipeline

Security headers → JSON parser (raw body kept for webhook signatures) → session → authenticate (session or bearer) → rate limit → CSRF → route guards (requireAuth → requireRole/requirePermission → requireChannelAccess → requireSubscription). Other tenants' resources return 404. Errors are thrown as AppError and rendered as {success:false, message, code}.

Database and migrations

  1. Edit shared/schema.ts (add new tables to MANAGED_TABLES).
  2. npx drizzle-kit generate --name my_change creates migrations/00NN_my_change.sql.
  3. Migrations apply automatically on start (and with npm run db:migrate). Never edit a migration that has run anywhere; add a new one.

Times are stored in UTC (datetime(3)). Secrets are encrypted with encryptStoredSecret.

Background work

Workers: WhatsApp message queue, email/SMS marketing worker, webhook deliveries, automation runs; plus scheduled jobs (server/cron/scheduler.ts). In database mode instance 0 polls; in Redis mode BullMQ ticks every server and claims rows atomically in MySQL. wakeWork(kind) nudges a worker after new work is queued.

Real-time

Socket.IO rooms per channel and user (realtime.toChannel, realtime.toUser); the Redis adapter spreads events across servers.

Tests

npm test runs unit and API tests (database access is mocked with spies on repositories). npm run check type-checks the whole project. Run both before a release.

Adding a feature

  1. Shared types and Zod schemas in shared/<feature>.ts.
  2. Schema + migration if needed.
  3. Service (logic) and repository (queries) in server/services.
  4. Controller and routes with the right guards; register them in server/routes/index.ts.
  5. Page in client/src/pages, route in App.tsx, menu item in app-layout.tsx, label in shared/platform.ts.
  6. Tests in server/__tests__.
